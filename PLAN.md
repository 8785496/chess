# План создания шахматной игры (React + TypeScript)

## 1. Обзор проекта

Клиентское шахматное веб-приложение: игра против бота (несколько уровней сложности),
подсказки и анализ позиций (движок Stockfish в WASM), библиотека классических дебютов
с пошаговым проигрыванием, мобильная адаптивная вёрстка и PWA (установка на устройство,
работа офлайн). Всё работает на клиенте — бэкенд не требуется.

## 2. Анализ npm-пакетов (проверено в реестре npm, сентябрь 2026)

### 2.1. Шахматная логика — `chess.js` v1.4.0 ✅ РЕКОМЕНДУЕТСЯ

- TypeScript-библиотека: генерация/валидация ходов, шах/мат/пат, FEN/PGN, аннотации.
- Актуальная версия 1.4.0 (июнь 2025), де-факто стандарт экосистемы.
- Альтернатива: `chessops` — быстрее, tree-shakable, но более низкоуровневая API
  (больше кода для типовых задач). Для нашего сценария `chess.js` проще и достаточна.

### 2.2. Доска (UI) — `react-chessboard` v5.12.1 ✅ РЕКОМЕНДУЕТСЯ

- React-компонент доски, активно развивается, используется на ChessOpenings.co.uk.
- Из коробки: drag & drop и tap-to-move (touch), подсветка ходов/клеток, кастомные
  фигуры, стрелки, анимации, кастомная рамка координат.
- Альтернатива: `cm-chessboard` v8.x — лёгкая SVG-доска без привязки к React
  (придётся писать React-обвязку). Или полностью своя SVG-доска — максимальный
  контроль, но заметно больше работы. Начинаем с `react-chessboard`, собственную
  доску оставляем как запасной вариант.

### 2.3. Движок (бот + анализ) — `stockfish` v18.0.8 ✅ РЕКОМЕНДУЕТСЯ

- Официальный WASM-порт Stockfish (поддерживается Nathan Rugg / Chess.com).
- В составе сборки: многопоточная, однопоточная, lite и lite-single версии + asm.js fallback.
- Управление по протоколу UCI из Web Worker.
- Особенности:
  - Пакет тяжёлый (все сборки сразу) — в бандл подключаем только нужную пару
    `stockfish-18-lite-single.js` + `.wasm` (~2–5 МБ), догружаем лениво.
  - Многопоточная версия требует SharedArrayBuffer → заголовки COOP/COEP.
    По умолчанию берём **однопоточную** (не требует спец. заголовков);
    многопоточную можно включать как опцию.
  - Лицензия GPL-3.0 — ок для открытого проекта, учитывать при коммерциализации.
- Уровни бота: через UCI-опции `UCI_LimitStrength` + `UCI_Elo` (примерно 1350–2850 Elo)
  и ограничение глубины/времени на ход.

### 2.4. Дебюты — датасет ECO ✅

- `@chess-openings/eco.json` v2.2.2 (MIT, июль 2026) — утилиты поверх датасета
  `eco.json` (проект lichess-org/chess-openings, ~3500 дебютов: ECO-код, название, ходы).
- Альтернативы: `chess-openings` v0.1.1 (Polyglot + ECO), `chess-opening-info` v1.1.1 (2021, устарел).
- Решение: бандлим JSON-датасет ECO (фильтруем до популярных ~100–200 дебютов,
  чтобы не раздувать бандл; полный датасет — опционально лениво).

### 2.5. PWA — `vite-plugin-pwa` v1.3.0 ✅ РЕКОМЕНДУЕТСЯ

- Zero-config PWA для Vite на базе Workbox: manifest, service worker, precache,
  runtime-кэширование, офлайн-режим, промпт установки.
- Отдельно кэшируем WASM-файл движка (cache-first) — после первого визита
  игра и анализ полностью работают офлайн.

### 2.6. Вспомогательный стек

| Задача | Пакет | Почему |
|---|---|---|
| Сборка | Vite | быстрый HMR, нативная поддержка WASM/Workers |
| Состояние | Zustand | минимализм, без бойлерплейта Redux |
| Стили | Tailwind CSS v4 | скорость вёрстки, удобный адаптив |
| Тесты | Vitest + React Testing Library | единая экосистема с Vite |
| Качество | ESLint + Prettier + typescript strict | — |

## 3. Архитектура

```
src/
  app/            # корневые компоненты, роутинг (игра / анализ / дебюты / настройки)
  core/           # обёртка над chess.js: сессия игры, контроль времени, история, экспорт FEN/PGN
  engine/         # менеджер Stockfish-воркера: UCI-адаптер, уровни бота, анализ (multipv)
  board/          # компонент доски, фигуры, диалог превращения пешки, стрелки/подсветки
  features/
    hints/        # подсказка хода (стрелка лучшего хода, оценка)
    analysis/     # шкала оценки, лучшие линии, разбор партии (классификация ходов)
    openings/     # библиотека ECO, поиск, пошаговый плеер дебюта
  pwa/            # конфиг manifest + service worker
  stores/         # zustand-сторы: game, settings, engine
  data/           # датасет дебютов (JSON)
  workers/        # загрузка и инициализация engine worker
```

Ключевые решения:
- **Движок изолирован в Web Worker** — UI не блокируется; один воркер переиспользуется
  для бота и анализа (или два при одновременной игре и разборе).
- **Единый источник правды по позиции** — экземпляр chess.js в сторе; UI — чистая проекция.
- **Ленивая загрузка движка** — начальная загрузка приложения лёгкая; WASM догружается
  при первом запросе хода бота/анализа и кладётся в SW-кэш.

## 4. Этапы разработки

### Этап 0. Каркас проекта (0.5–1 день)
Vite + React + TS (strict) + Tailwind + ESLint/Prettier, структура папок, CI-скрипты.

### Этап 1. Доска и правила (2–3 дня)
- Доска `react-chessboard`: ходы drag & drop + tap (мобильные), подсветка возможных
  ходов, последнего хода, шаха.
- Полные правила через chess.js: рокировка, взятие на проходе, превращение пешки
  (диалог выбора фигуры), мат/пат/ничьи (50 ходов, троекратное повторение, недостаток материала).
- История ходов (SAN), откат хода, экспорт FEN/PGN, переворот доски, выбор цвета.

### Этап 2. Игра с ботом (2–3 дня)
- Web Worker + UCI-адаптер Stockfish (init → isready → position → go).
- 5 уровней сложности (от новичка до сильного): `UCI_Elo`/`Skill Level` + лимиты
  depth/movetime для отзывчивости на слабых устройствах.
- Игровой цикл: ход игрока → ход бота (с индикатором «думает»), прерывание,
  новая партия, контроль времени (опционально).

### Этап 3. Подсказки и анализ (3–4 дня)
- **Подсказка хода**: кнопка «Подсказать» → лучшая линия от движка, стрелка на доске.
- **Оценка позиции**: вертикальная шкалы оценки (centipawns → «+1.2»), обновляется
  после каждого хода.
- **Разбор партии**: прогон сыгранной партии через движок, классификация ходов
  по потере очков (отлично/неточно/ошибка/зевок) с аннотациями в списке ходов,
  переход по ходам с оценкой на каждый.
- Настройка глубины анализа (быстро/точно).

### Этап 4. Дебюты (2–3 дня)
- Датасет ECO (отфильтрованный список классических дебютов: итальянская, испанская,
  сицилианская, ферзевый гамбит и т.д.).
- Каталог: поиск, фильтр по ECO-коду/названию, карточка дебюта.
- Плеер: пошаговое проигрывание ходов (вперёд/назад/автоплей) с подсветкой,
  названием варианта на каждом шаге, возможностью продолжить «с этой позиции» против бота.

### Этап 5. Мобильная вёрстка и PWA (2–3 дня)
- Адаптив: доска = `min(100vw, доступная высота)` через ResizeObserver/`dvh`,
  панель ходов/контролов под доской на мобильных и сбоку на десктопе;
  safe-area insets (вырез/жест-бар); блокировка скролла при перетаскивании фигуры.
- `vite-plugin-pwa`: manifest (иконки, тема, orientation), precache app shell,
  runtime cache для WASM движка и спрайтов фигур; офлайн-режим; промпт установки.
- Проверка на реальных устройствах (Chrome/Safari, iOS: установка на «домашний экран»).

### Этап 6. Полировка (2–3 дня)
- Темы доски/фигур, звуки (ход/взятие/шах, с переключателем), анимации,
  тёмная/светлая тема, i18n (ru/en), сохранение настроек и истории партий
  в localStorage/IndexedDB.

### Этап 7. Тестирование и релиз (1–2 дня)
- Unit-тесты логики (Vitest): правила, UCI-адаптер (мок-воркер), классификация ходов.
- Component-тесты: доска, плеер дебютов.
- Lighthouse: PWA-аудит, производительность; сборка и деплой (например, GitHub Pages /
  Netlify — статика, специальные заголовки не нужны для single-threaded движка).

**Итого: ~15–20 дней разработки.**

## 5. Риски и их снижение

| Риск | Решение |
|---|---|
| Большой размер WASM-движка при первой загрузке | lite-single сборка, ленивая загрузка, SW-кэш |
| Многопоточный WASM требует COOP/COEP-заголовков | по умолчанию однопоточная сборка |
| Просадки производительности анализа на слабых телефонах | лимиты depth/nodes, «лёгкий» режим анализа |
| Breaking changes `react-chessboard` (v4→v5 были) | фиксировать мажорную версию, изолировать доску в компоненте-обёртке |
| GPL-3.0 у Stockfish | проект открытый; при коммерциализации — отдельная оценка лицензий |
| Размытие/скролл на iOS при drag фигур | touch-action/overscroll-behavior, preventDefault в обработчиках |

## 6. Критерии готовности (Definition of Done)

1. Партия против бота на 5 уровнях с полной реализацией правил, откатом хода и экспортом PGN.
2. Кнопка подсказки и шкала оценки работают на любой позиции.
3. Послематчевый разбор с классификацией ходов.
4. Каталог ECO-дебютов с пошаговым плеером (≥100 дебютов).
5. Lighthouse PWA-аудит ≥ 90; офлайн-режим: партия с ботом без сети после первого визита.
6. Удобная игра на экране от 360 px шириной; установка на домашний экран (Android/iOS).
